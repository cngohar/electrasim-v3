# Simulator and account circuits — Phase 1.5

Development is local only. Start `bun run dev:worker` (127.0.0.1:8791) and `bun run dev` (port 3000). Vite proxies `/api` to that local Worker. Apply migrations with `bun x wrangler d1 migrations apply DB --local --persist-to .wrangler/state`. No Cloudflare account or deployment is needed.


Phase 1.5F.1 calculation consumers require `inputRevision` plus the current electrical model version. The identity canonicalizes normalized electrical inputs while excluding canvas geometry/selection; it is freshness metadata, not authorization. Scalar/complex readings retain their named terminal pairs and independent references. Missing, stale, obsolete or unassessed evidence cannot earn a validator/guide pass. Exports recalculate their snapshot, and version-2 guide history preserves earlier records as historical checklist progress. Tagged legacy observation flags cannot certify repair, protection or safety. [Consumer acceptance](../audits/phase-1-consumer-integration.md).

Phase 1.5F.2 diagnosis attempts use generator **3** and an authored `assessment` containing assessment version 1, model/engine versions, `diagnosis-profile-score-1`, and exact healthy/faulted electrical revisions. New generation selects six supported resistive/manual/declared-coil topologies and observable supported faults. Submission recalculates the authored and submitted circuits; removal, identification and operating-point recovery remain separate. Every authored component identity/model/rating, source profile, terminal connection and conductor property must be preserved. Equivalent replacement cables and geometry changes are permitted. A recovered named load must match its actual baseline voltage/current/power. Success establishes restored teaching operation, not installation safety or standards compliance. [Scope and acceptance](../audits/phase-1-diagnosis-integration.md).

Older attempt snapshots remain readable. GET adds `assessmentIssue`, includes `scoreEvidence` and reports `readOnly` when assessment versions/snapshots differ, independently of membership. New attempts accept only the current generator. An obsolete active attempt rejects submit/hint/expire with 409; authorized checkpoint/abandon retain the earlier elapsed time and do not invent new grading penalties. Existing terminal scores retain their historical evidence. Current share codes pin model/engine/profile versions; IndexedDB resume restores the original scenario and repaired drawing rather than regenerating it silently.

## Authorization

Basic editing, simulation, single basic faults and basic diagnosis run locally without a session or network. Premium editor mutations and simulation request fresh membership from primary local D1. A local capability snapshot drives presentation, not authorization. Every server endpoint derives requirements from validated component types and normalized faults. Advanced diagnosis and every Ohmageddon tier add their own requirements from the stored scenario.

The browser remains user-controlled; supported editor flows are gated, while server content delivery and accepted results enforce authorization independently. Server mutations repeat capability predicates with the owner/version condition inside their SQL write, so concurrent revocation or a stale version cannot silently overwrite work. Failed writes do not increment versions or diagnosis counters.

## Endpoints

All mutation bodies are JSON, require a matching Origin, and reject unknown fields. Responses are private/no-store. Account routes require a real Better Auth session cookie.

| Route | Body or result |
| --- | --- |
| `POST /api/simulator/authorize` | `{ circuit, diagnosis? }`; validated requirements and current membership |
| `POST /api/simulator/simulate` | `{ circuit, standard?, simulationState?, deltaSeconds? }`; authorized solver result (Sets serialized as arrays); maximum 500 components / 1,000 wires |
| `GET /api/circuits?limit=…&offset=…` | Owner's paginated metadata |
| `POST /api/circuits` | `{ name, circuit }`; new document/version |
| `GET /api/circuits/:id` | Owner's original content, version, requirements, readOnly flag |
| `PATCH /api/circuits/:id` | `{ name, circuit, version }`; checks both existing and replacement content |
| `DELETE /api/circuits/:id` | `{ version }`; owner may delete after downgrade |
| `POST /api/diagnosis/attempts` | `{ seed, difficulty, rageTier?, generatorVersion? }`; server-generated scenario, repair circuit, progress and version |
| `GET /api/diagnosis/attempts/:id` | Owner's preserved scenario, repair circuit and accepted progress, including after downgrade |
| `POST /api/diagnosis/attempts/:id` | `{ action, version, circuit, answer? }`; actions submit, hint, checkpoint, abandon, expire |

Diagnosis submissions provide only the answer and repaired circuit. The server owns the original scenario, identified fault IDs, counters and accepted score. It evaluates recovery itself. The active-time model banks at most the 30 seconds since the prior accepted action; the browser checkpoints every 15 seconds. A denied/offline request does not update stored time. This is a local teaching score, not a competitive timing or anti-cheat service.

Completed and timed-out attempts return the same server-derived score on subsequent reads. Confirmed terminal actions leave the local active record and update aggregate statistics; a reload can recover a finish that was accepted before its response arrived. Further mutations of a finished attempt return 409.

## Persistence and recovery

Circuit-file and portable-backup writers emit schema 2 and accept schemas 1 and 2 on import. The raw `Circuit` in API bodies retains component configuration, typed document/independent source profiles, structured faults and legacy fields. Schema-1 documents migrate with their IDs and explicit ratings intact; omitted frequency remains the documented 50 Hz assumption. Autosaves upgrade under the existing IndexedDB key. Import, share, autosave, account loads and saved premium documents may open read-only. Editing, undo/redo, pasting and simulation check the original document and any newly required capabilities, including supply-only changes. A denied or stale asynchronous edit does not consume undo history.

“Create basic copy” lists removal choices explicitly, validates that the result requires no premium capabilities, writes the original to IndexedDB recovery storage, and only then opens a separate copy. Saved originals can be downloaded under Saved circuits. Raw JSON export remains available. Failed backup storage cancels replacement.

Diagnosis version 2 chooses basic-eligible recipes/faults before generation. Version 1 tickets retain their original generation inputs. Active records now retain repair circuits and original scenarios alongside seed/version and counters. Denied or unsupported restores retain their stored records and expose recovery; expiry does not delete learner work.

## Local verification

Phase 1.5B added a pure `compileCircuit` domain entry point and additive `electricalContract` metadata on simulation results. Compilation validates the document and reports graph/model coverage; it is not a numerical solve or a new HTTP endpoint. At that milestone the API still ran the guarded legacy solver. See [electrical contracts, defaults and topology](../audits/phase-1-electrical-contracts.md) for versions and compatibility boundaries.

Phase 1.5C.0 adds pure capability, terminal-compatibility and readiness services. Electrical contract version is 1 and model version is `1.5c.0.1`; persisted DC, reserved three-phase and mixed/conflicting supplies remain guarded from unsupported legacy measurements. `bun run verify:phase-1.5c0` passed 494 Bun/local Hono-workerd parity cases, 9 Worker/D1/cookie groups and 59 browser cases. See [supply profiles and preflight acceptance](../audits/phase-1-supply-preflight.md); the MNA solver and full consumer migration remain later steps.

The pure `solveCircuit` entry point uses engine `mna-linear-2`, contract 1 and shared model/capability version `1.5e.2.1`. It returns fixed-resistance/wire operating points, coupled isolated AC transformer measurements, separate galvanic references, PE/bond/continuity findings and explicitly limited fault-current estimates. Unknown measurements are unavailable, and installation/clearing assessments remain unassessed. The [transformer/PE acceptance](../audits/phase-1-transformers-pe.md) records the earlier numerical gate. **Phase 1.5C.5 connects these supported results to `simulate()`, the real browser Comlink worker and `POST /api/simulator/simulate`.** No new application endpoint was introduced.

**Phase 1.5E.0** adds a separate domain-only `solvePhasorCircuit()` entry in `@electrasim/domain/core` with engine `mna-phasor-resistive-1`. Explicit source models declare `phasePorts: [L1, L2, L3]` and `ports: [L1, N]`; source voltage stays RMS L-N. The result carries complex RMS terminal/branch voltages and currents, `branchActivePowersWatts`, `wireLossesWatts`, independent reference domains and complex conservation checks. Use `phasorVoltageBetween()` before `phasorMagnitude()` for L-L measurements; subtracting scalar RMS magnitudes cannot give that voltage. Independent unsynchronized AC systems joined into one domain and unknown motor/reactive/timed models remain unsupported. Operation, repair and standards remain unassessed. `solveCircuit()` remains a scalar entry and rejects phase systems. **E.1 adds the free `ac-three-phase-supply` catalogue entry with saved L1/L2/L3/N/PE indices 0/1/2/3/4.** `simulate()`, Comlink and the existing local Hono endpoint dispatch explicit phase systems to the phasor solver and return `phasor` plus named `phasorComponents` display readings. No scalar `electrical`/`componentCalculations`, clock, protection step or thermal state is synthesized. `faultsCleared` remains false and operation/repair/standards are unassessed. The named source confirmation supports L-N/L-L voltage, frequency and ABC/ACB sequence with Cancel/Apply/Undo and running/exercise locks. E.2 motor/control operation is described below; E.3 DOL/full teaching acceptance and F.1/F.2 consumer/lab migration are accepted locally; F.3 retirement/full integration acceptance remains open. This adds no HTTP endpoint. [E.1 scope and acceptance](../audits/phase-1-three-phase-source.md). [Scope and local gate](../audits/phase-1-phasor-foundation.md), [ADR 0014](../decisions/0014-resistive-three-phase-phasors.md).

**Phase 1.5E.2** adds opt-in `ComponentState.motorModel` version 1 with `kind: balanced-resistive`, `nominalLineVoltage`, `inputPowerWatts`, `frequencyHz`, `operatingLineVoltageRange: { min, max }`, `maximumUnbalanceRatio` (0–0.1) and `requiredSequence: abc | acb`. The model requires the canonical `motor-3phase` U/V/W terminals. `phasor.motors` reports teaching operation, connected phases, terminal sequence, actual L-L voltages/line currents, passive-equivalent input power and unbalance. Three distinct conductive phases, declared frequency/balance/range and compatible equipment ratings are required for `running`; backfed voltage alone cannot establish a phase. It is a unity-PF delta approximation, with mechanical/reactive/transient behavior unassessed.

The three-pole contactor appends A1/A2 at indices 6/7 while preserving power indices/anchors 0–5. Explicit AC coils now advance through the existing `simulationState`/`deltaSeconds` API using **mna-phasor-controls-1**. `phasor.controls` carries complex RMS coil readings and pending transitions; `simulationEvents` carry pre-event RMS magnitudes tagged `measurementConvention: complex-rms-magnitudes`. `coilStates` and measurements reflect the final topology. State validation, microsecond resolution and bounds are shared with the scalar runtime; malformed/obsolete state and invalid deltas return HTTP 400. `phasor.deviceCurrents` reports signed complex sensed-pole currents, maximum pole RMS current, contact capacity and residual mA from the vector sum. Poles in independent reference domains report `residualUnavailableReason: independent-references` instead of a fabricated sum; unavailable branch currents report `missing-current`. Coil and bypass currents are separate; automatic protective clearing and damage remain unassessed. Shared model/capability version is **1.5e.2.1**; schemas are unchanged. Existing paid motor/contactor requirements still return 401/403 for missing authorization. No endpoint or repair/scoring verdict is added. [E.2 scope and acceptance](../audits/phase-1-three-phase-motor.md), [ADR 0015](../decisions/0015-three-phase-motor-controls.md).

**Phase 1.5D.0** adds opt-in `ComponentState.coilModel` version 1 and deterministic control steps through the same `simulate()` options and calculation endpoint. Supply, real power, pickup/dropout ratios and on/off delays are declared independently of the contact ratings. Returned `simulationState` is transient; omit it to reset time and integrators, preserving saved damage flags in the input. `deltaSeconds` defaults to zero, is bounded to 0–3600 seconds and uses microsecond clock resolution. State includes the current model and configuration identity; malformed/obsolete state or an invalid delta produces HTTP 400. Returned `simulationEvents` contain pre-event coil readings, while `electrical.controls` and ordinary readings describe the final topology. D.0 introduced `mna-controls-1`, D.1 `mna-controls-2`, D.2 `mna-controls-3`, and D.3 supersedes them with `mna-controls-4`. Replay requires the same input sequence and model version. Caller state is not accepted by exercise scoring. [Scope and acceptance](../audits/phase-1-timed-controls.md).

**Phase 1.5D.1** adds optional `ComponentState.timerModel` version 1 through the same boundary. Daily/weekly schedules declare a cycle, offset and up to 32 separated half-open ON intervals. Staircase/countdown programs declare a duration and restart/ignore retrigger behavior. Two-terminal clocks are external; countdown electronics require a declared resistive supply across L-in/N-in and reset on power loss. `on` enables a schedule or supplies the interval's rising-edge trigger. `simulationState.timers` carries transient input latches/deadlines; neither it nor derived contacts belong in saved circuits. `electrical.timers` and `timerContactStates` describe final clock/contact operation, and timer events carry the pre-event pole current. Equivalent JSON field order does not change configuration identity.

Dimmer `speed` uses 0–3 for light controls and the existing 0–5 fan-regulator range, with omitted levels defaulting to full output when enabled. `simulate()` uses ideal synchronous switching for supported resistive AC networks, reporting sample-derived RMS voltage/current and mean real power under `electrical.dimming`; inspect terminal pairs rather than subtracting RMS potentials. Standalone dimming uses `mna-dimming-1`; timed calls use `mna-controls-4`. Unsupported LED/motor laws, DC control, affected reactive excitation and numerical limits remain unassessed. Existing static fan/driver exercises may retain tagged qualitative continuity, without numerical telemetry. Paid catalogue requirements are unchanged: missing sessions receive 401 and signed-in users lacking the benefit receive 403. See [D.1 scope and acceptance](../audits/phase-1-timers-dimming.md) and [ADR 0011](../decisions/0011-rms-dimming-and-timer-programs.md).

**Phase 1.5D.2** adds opt-in `ComponentState.protectionModel` version 1 for the automatic MCB/fuse/RCD/RCBO families. Declared ratings, curves, I²t anchors and residual bands are driven by measured pole branch currents. D.3 makes the bypass teaching assumption explicit: disconnect the sensed ideal contact and route current through an external shunt, including with an open/tripped handle. It does not estimate current sharing through a real parallel bridge. Resettable overload/residual trips latch open until OFF or a fresh run, and events carry pre-event pole currents, current multiple and residual mA. Static `solveCircuit()` never trips. Ordinary trip latches are transient; D.3 fuse operation uses the distinct `fuse-operated` event, survives OFF/ON and requires replacement. See [D.2 scope and acceptance](../audits/phase-1-protection.md) and [ADR 0012](../decisions/0012-timed-protection-models.md).

**Phase 1.5D.3** implements opt-in cumulative damage and separate Fault Lab clear/reset/replace actions. Its [acceptance record](../audits/phase-1-damage-repair.md) records the complete local gate, including 705 Bun/workerd cases, 15 Worker/D1/session groups and 63 Chromium cases. [ADR 0013](../decisions/0013-damage-and-repair.md) defines the teaching law and persistence boundary. Supported resistive loads accept `ComponentState.damageModel`; wires accept current models through `WireInstance.damageModel`:

| Version 1 model | Threshold field | Budget field | Allowed subjects |
| --- | --- | --- | --- |
| `kind: "overcurrent"` | `continuousCurrentAmps` | `withstandAmpSquaredSeconds` | Supported resistive loads and wires |
| `kind: "overvoltage"` | `maximumVoltageVolts` | `withstandVoltSquaredSeconds` | Supported resistive loads |

Each object requires `version: 1`, its kind and the two corresponding fields; extra fields are rejected. Thresholds are finite numbers from 0.001 to 100,000, and budgets from 0.000001 to 1e12. Exposure integrates `max(measured² − threshold², 0)` over simulated seconds using actual branch DC/RMS current or the load terminal-pair voltage. The element opens at the first microsecond at or after its budget crossing. Missing declarations and static damage coverage are unassessed; ratings never imply temperature, fire, cooling or lifetime predictions.

`simulationState.damage` keys encode `[target.type, target.id]`, with cumulative exposure, the previous stress rate and the open latch. `electrical.damage` describes final readings and pending crossings. Each `damage` event identifies its component/wire target and retains the pre-event current/voltage, budget, exposure and simulated timestamp. The clock integrates through every requested boundary before accepting later inputs, and solves again after an opening. Obsolete model state or changed damage configuration requires reset.

The app projects irreversible damage and fuse operation into saved `isBlown` / `isBusted` flags, preserving them through export/import and recovery; transient exposure is not saved. Pure domain/API calculations do not mutate the input document. Stop/Run resets time and resettable trips without replacing saved failed items; the app requires replacement/reset before restarting a drawing with those flags. Clearing injected faults preserves damage and trips. Reset selects OFF; replacement requires a stopped run and preserves remaining faults, wiring and ratings. An unchanged cause can damage the replacement again. Existing membership and exercise constraints apply, and caller state remains excluded from exercise scoring.
